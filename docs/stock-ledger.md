# ELIFORA Phase 4C stock ledger

Inventory is location-owned operational truth. It does not confer product verification, technical compatibility, safety approval, price, cost, margin or profitability. `catalog_product_id` points to an immutable product version; `catalog_series_id` is derived by the writer and maps later technical versions of that same product series to the location card. New global/salon mappings must reference active, verified, published products and use the existing catalog lifecycle lock and authoritative re-read. Custom operational items cannot enter Brand Adapter recipes.

`stock_movements` is append-only. On-hand is `SUM(quantity_delta)`, reconstructed under RLS rather than stored in a browser or mutable balance field. Nonzero opening, receipt, adjustment, reversal, usage and correction entries carry actor, effective timestamp, reason, correlation and mutation IDs. `stock_openings` separately retains explicit measured zero; an item without a measured opening has UNKNOWN quantity. GRAM and MILLILITER have two decimal minor units; UNIT requires integers. The RPC rejects additional decimals before a numeric column could round them. No density conversion exists.

Normal authenticated/anonymous/service roles cannot insert, update or delete inventory records. The NOLOGIN/NOBYPASSRLS stock writer owns the guarded RPCs. RLS checks current database membership, organization, location and stock.view on every tenant row. Operations require stock.receive, stock.adjust, stock.count, stock.manage_items or stock.manage_lots as appropriate, plus a fresh selected membership. Audit events use the existing immutable audit table. Historical movement actors are independently scoped to organization memberships; technical actor/source facts remain in their original domain.

Permanent `(organization, actor, mutation)` receipts return the exact accepted output for the same payload and location, including controlled delivery failures. Changed payloads conflict. Source delivery separately deduplicates `(domain, source event, bowl, product)` and has a unique movement source-event ID; changing a browser mutation ID never duplicates source consumption. Error receipts are not authorization grants: membership is checked before every replay.

Manual balance decisions lock the item row. Queue delivery locks event → item → optional lot, then re-reads the authoritative technical amount and existing applied consumption. Count confirmation additionally serializes with enqueue on the location cutover row. No broad organization advisory lock is used for ordinary stock posting. Mutation advisory locks protect only one receipt identity. Multiple-item counts lock items in sorted UUID order.

BLOCK_NEGATIVE is the default. WARN_NEGATIVE is an explicit versioned, audited location policy. Policy changes and negative overrides are audited. A shortage in actual technical usage leaves a FAILED source event and operational discrepancy; it never rewrites the Live Session. Manual source-consumption reversals are rejected; factual technical changes must use the append-only reconciliation chain.

Web: `/workspace/stock`, authenticated `/api/stock`. Android uses `stock_snapshot` for authoritative decimal list/detail/status/history and revalidates memberships before releasing data. Shared OpenAPI 0.17.0 and runtime-generated JSON schemas live in `contracts/stock.schemas.json`. Direct RPC validation mirrors Web request shapes, types, scope restrictions and quantity precision.

Source-driven stock actions reuse the operational Action Center entry boundary with CRM. LOW_STOCK, OUT_OF_STOCK, USAGE_RECONCILIATION_REQUIRED, UNIT_MAPPING_REQUIRED, STOCK_SYNC_FAILED, PRODUCT_MAPPING_REQUIRED and expiry signals are computed from current authoritative records, not procurement tasks or fake client CRM rows. Saving recipes only displays availability for already verified compatible selections; it never substitutes an unverified or incompatible product.

Transfer movement vocabulary and linked transfer identity are reserved in the ledger, with no public transfer mutation. Paired cross-location transfer workflow, reservations, valuation, acquisition costs, camera scanning and supplier purchasing are deliberately deferred. No Finance or Phase 5 work is included.
