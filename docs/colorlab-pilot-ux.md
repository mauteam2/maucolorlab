# ELIFORA ColorLab pilot UX

The existing ivory/plum/copper system, approved integrated f-brush logo and 1,500 ms
sign-in intro remain unchanged. Only the target workflow and result explanation grow.

Select the client and inspect Hair Passport. Fast presets or depth → family → region
scope create explicit targets. The professional regional editor preserves existing
additional fields and adds optional secondary direction. Advanced regional controls are disclosed progressively; stored correction/isolation settings remain visible. A preflight summary shows
the current regional level, grey ratio, evidence presence and desired target; it is
editable before the existing authenticated server evaluation.

Results distinguish target, risk, evidence confidence, feasibility, strategy, recipe
availability and prerequisites. Turkish labels explain reasons, regional handling and
checkpoints. Multi-session is a usable strategy with an explicit reassessment step,
not a failed request. Where no safe intermediate level is evidenced, the professional
must establish it after testing; no date or lift outcome is promised.

Manufacturer selection is downstream. Existing controlledOptions states remain the
source of recipe availability: OPTIONS_FOR_REVIEW, ASSESSMENT_REQUIRED,
NO_VERIFIED_MATCH, BLOCKED_BY_SAFETY, CATALOG_UNAVAILABLE. Each has a Turkish
explanation. A useful generic plan can have no verified brand mapping. No shades,
grams, ratios or processing time are inferred from the desired target.

All swatches have text/radio selected semantics. They are illustrative family aids,
not photographic predictions. Lists wrap at 320 px and no large horizontal grid is
introduced. Region edits, offline drafts and generation/visibility concealment remain
in the original workspace. Sync does not bypass current Hair, version, catalog,
membership, entitlement or risk checks. Offline target drafts never execute chemistry.
